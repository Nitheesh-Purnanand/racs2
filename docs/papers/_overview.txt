RACS — Final Project
Overview
Retrieval-Augmented Coverless Semantic
Steganography
Purpose:  Compact, complete project specification for an LLM or developer . It defines the original
AgentSemSteCom system, the RACS modification, architecture, token/security design, implementation
boundaries, evaluation, risks, hypotheses, and success criteria. It intentionally removes repetition from the longer
overview .
1. Project Definition
RACS (Retrieval-Augmented Coverless Semantic Steganography)  starts from the 2026 IEEE paper “Secure
Intellicise W ireless Network: Agentic AI for Coverless Semantic Steganography Communication.”
The paper's AgentSemSteCom  combines:
agentic semantic extraction,
implicit structural features,
diffusion-based reference-image generation,
EDICT -based reversible dif fusion,
digital-token security ,
semantic communication,
wireless transmission,
optional task-oriented enhancement.
Problem
The original system generates a reference image through an expensive dif fusion process. RACS investigates:
=== PAGE 2 ===
Can retrieval-based reference-image acquisition provide suf ficiently compatible semantic and structural
conditioning for reversible coverless steganography while reducing the computational cost of reference
generation?
RACS does not assume retrieval is better . It is a quality-security-robustness-ef ficiency comparison.
Core modification
AgentSemSteCom:  
Secret → Kpub + Xfeat → diffusion generation → Xref  
RACS:
Secret → Kpub + Xfeat → retrieval → reranking  
      → token-controlled selection → optional light editing → Xref  
The downstream EDICT , token perturbation, semantic communication, channel and recovery pipeline should initially
remain unchanged.

2.2 Stage 1 — Semantic extraction
Public semantic key:
Kpub = fLLM(Xs)  
Kpub  describes what the secret image contains.
Implicit structural feature:
Xfeat = G(Xs, R)  
Xfeat  describes structural/layout information. The paper discusses:
semantic segmentation for common images,
OpenPose skeletal landmarks for facial images,

style-related conditions where explicit reference features are not required.
Core distinction:
Kpub  = semantic/content information  
Xfeat = structural/layout information

7. Digital Token in RACS
The token should be retained but its reference-acquisition role changes.
Original:
Token → diffusion noise seed  
RACS:
Top-K candidates  
      ↓ 
Token
      ↓ 
deterministic mapping  
      ↓ 
selected candidate  
Example conceptual mapping:
=== PAGE 13 ===
index = H(token) mod K  
The exact mapping must be fixed.
Quality constraint
Never use:
Token → arbitrary database image  
Use:
Query
 ↓ 
Top-K relevant candidates  
 ↓ 
quality filtering/reranking  
 ↓ 
valid candidate pool  
 ↓ 
token selection  
The token provides controlled diversity/security while preserving candidate quality .
Security hypothesis
If the valid candidate pool has size K:
P(correct reference | no token) ≈ 1/K  
and a simple uncertainty measure is:
log2(K) bits  
This is only a research model, not a complete security proof. A full analysis must consider token entropy , database
knowledge, ranking knowledge, candidate filtering, side information, and attacker capabilities.

One-sentence definition
RACS is a retrieval-augmented coverless semantic steganography framework that replaces the
computationally expensive dif fusion-based reference-image generation stage of AgentSemSteCom with
deterministic multimodal retrieval and optional lightweight structural editing, while preserving the
downstream EDICT -based hiding/recovery and semantic communication pipeline for a direct quality ,
security , robustness, and ef ficiency comparison.
